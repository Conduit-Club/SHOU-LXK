# 课程与老师补充审核

课程和老师目录各有补充入口，统一进入 `/submissions`。登录并完成用户名资料后可提交，默认点评仍直接公开，不加入此审核队列。游客可浏览补充说明与登录入口，自己的提交列表按会话作者编号查询，不接受 URL 或表单指定作者。

老师填写姓名与可选说明。课程填写课程号、名称、已知学院、类型与 0–30 的整数学分，班级编号可选；与当前目录 INTEGER 学分模型保持一致，不编造未知学院、类型或学分。没有真实班级编号时，审批创建 `community-<submission UUID>` 内部课段，界面称为“补充收录”，可以直接写点评。第一版只新增课程和老师，不改既有课程、课段或授课关系。

待审内容只存私有 `catalog_submissions`，不写公共表，不进入目录、详情、首页缓存或统计。提交者可查看自己的原始信息、状态和审核理由。认证中心管理员在 `/admin/submissions` 按类型、状态和姓名/课程号筛选，核对或修正收录信息；通过与拒绝都要求 1–500 字理由，原始提案保持不变，批准快照和操作者写入审计。

提交要求本站会话、完整用户名、同源 POST、CSRF 与 `submit_catalog` Turnstile。表单 UUID 保证同一次提交的重试不重复写入；待审唯一索引防止多账号重复提交。老师名称 NFKC/trim 归一后按 SQLite NOCASE 的 ASCII 折叠去重，非 ASCII 大小写保持区分；没有宣称全 Unicode 姓名唯一。课程号转大写。已有目录目标拒绝再次补充。

写入内再次验证会话、issuer、用户名和本站封禁；每账号每小时最多 5 条、每天 20 条，同时待审最多 10 条，计数使用作者索引，并发无法绕过。审核事务复用中心管理员短期角色与会话检查，先插入条件审计，再据同一 operation 发布老师或课程与课段、增加筛选选项并记录决议。任何失败都回滚目录、计数、审计和状态，重复审批返回 409。只有 pending 能进入终态，原始资料与审计不能 UPDATE；拒绝不写公共表。

批准后清除当前数据中心的首页统计、最新收录与筛选项缓存；公共目录和详情直接查库。其他中心/并发回填仍受原 TTL 约束，首页最长约 60 秒，筛选选项最长 6 小时。游客布局和公共目录不新增队列计数或读取。

`0009_catalog_submissions.sql` 只有 2 个新空表、4 个索引与 4 个触发器，共 10 条 DDL；没有历史读取回填、重建或重放。已应用 0008 的库仅应用缺失的 0009；新空库直接用 `schema.sql`，不要再重复结构迁移。上线前按私有数据备份数据库，由维护者执行远程迁移后再发布。

本地关键测试在 `tests/catalog-submissions.test.mjs`：私有性、身份/CSRF/验证码拒绝、原始数据保留、点评即时公开、限频与并发去重、批准/拒绝、计数/缓存与失败回滚、请求途中撤权/封禁。`pixi run build` 后运行 `pixi run pnpm test:http`，对实际生产构建的 SSR Request/Response 与临时 workerd D1 验证游客/普通用户无管理 UI、伪造开关和直接管理动作被独立拒绝。所有 fixture 仅在临时本地数据库，绝不连接生产。
